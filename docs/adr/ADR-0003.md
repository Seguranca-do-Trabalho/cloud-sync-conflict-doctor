# ADR-0003 — Report schema v1 and determinism rule

- **Status:** Accepted
- **Date:** 2026-08-22
- **Decided by:** Orchestrator (card T03)

## Context

§3 requires that the same tree produces a **byte-for-byte identical** report, regardless of enumeration order, threads, or hash maps. §13 mandates a single domain model feeding both JSON and GUI.

## Decision

Versioned JSON schema:

```json
{
  "report_schema_version": 1,
  "algorithm": "BLAKE3",
  "hash_version": 1,
  "generated_from": { "root_path": "<scanned path>", "scan_started_utc": "...", "scan_finished_utc": "..." },
  "telemetry": {
    "files_enumerated": 0, "files_skipped": 0, "files_placeholder": 0,
    "files_partial_hashed": 0, "files_full_hashed": 0,
    "bytes_read": 0, "bytes_read_partial": 0, "bytes_read_full": 0,
    "placeholder_bytes_read": 0
  },
  "groups": [ ... ],
  "identical_duplicates": [ ... ],
  "real_conflicts": [ ... ],
  "placeholders": [ ... ]
}
```

Determinism rules (mandatory, tested):

1. Serialization always operates on structures sorted by **path in UTF-8 bytes** (not locale).
2. Tie-breaking in any decision: `mtime` → `size` → `path`. Never "first seen".
3. `scan_started_utc/finished_utc` are outside the lists; no list contains incidental time fields.
4. CI test: 3 scans on the same synthetic tree with different enumeration orders → output files byte-for-byte identical.

## Consequences

- GUI has no second logic engine; it consumes exactly this schema.
- Changing hash/algorithm = bump `hash_version`; changing format = bump `report_schema_version`.
