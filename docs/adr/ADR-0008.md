# ADR-0008 — CLI: System.CommandLine with stable exit codes

- **Status:** Accepted
- **Date:** 2026-08-22
- **Decided by:** Architect (card T01)

## Context

§14 mandates CLI from day one (`conflictdoctor scan <path> [--json] [--quiet]`), JSON mode suitable for scripts/RMM/automation/tests, documented and stable exit codes, without degrading GUI UX. §26/CANALS.md: offline operation, no network.

## Decision

1. **`System.CommandLine`** package (pinned version) in `src/Doctor.Cli`; executable `conflictdoctor`.
2. v1 surface:

```text
conflictdoctor scan <path> [--json] [--quiet] [--output <file>] [--read-parallelism N] [--no-cache]
```

Resolution/quarantine commands (`quarantine apply`, `quarantine restore`) inherit this same exit code table when they exist — defined now to avoid migrating the contract later.

3. Stream discipline: `stdout` reserved for results (`--json` ⇒ pure JSON, zero noise; without `--json` ⇒ human summary); progress and diagnostics ⇒ `stderr`; `--quiet` silences progress, never errors.
4. **Official exit code table** (stable; new case enters a new code, never recycled):

| Code | Meaning |
|---|---|
| 0 | scan completed; no relevant anomaly (no duplicate/real conflict) |
| 1 | operational error (path nonexistent/inaccessible, fatal I/O failure, incorrect argument usage) |
| 2 | scan completed; conflicts/duplicates found |
| 3 | operation partially completed (some files could not be processed; report emitted with error list) |

Precedence: `1` > `3` > `2` > `0`. Operational error dominates; without error, partial dominates; without partial, findings dominate.

5. The `--json` output is **exactly** the schema from ADR-0003 (`report_schema_version = 1`); no parallel output format.
6. Zero telemetry, zero network call, zero online verification (§26); suitable for offline RMM (CANALS.md).

## Consequences

- GUI consumes the same engine and same schema; CLI carries no scan logic of its own.
- CLI tests validate the four codes and stdout purity in `--json` mode.
