# ADR-0006 — Incremental cache: SQLite via Microsoft.Data.Sqlite

- **Status:** Accepted
- **Date:** 2026-08-22
- **Decided by:** Architect (card T01)

## Context

§12 mandates local cache in SQLite with minimal model (`file_id, size, mtime, hash_partial, hash_full, algorithm, hash_version, last_seen`), logical key by **file ID/inode** (not path) so that renaming/moving does not invalidate cache. ADR-0001 already fixed `Microsoft.Data.Sqlite`.

## Decision

1. **`Microsoft.Data.Sqlite`** package pinned; single database at `%LOCALAPPDATA%/ConflictDoctor/cache.db` (shared by CLI and GUI). WAL enabled; exclusive process access — no server, no network (§26).
2. Schema v1:

```sql
CREATE TABLE IF NOT EXISTS file_hash_cache (
    volume_id     TEXT NOT NULL,          -- volume identity (file ID is only unique within it)
    file_id       TEXT NOT NULL,          -- NTFS file ID / inode-like, as stable text
    size          INTEGER NOT NULL,
    mtime_utc     TEXT NOT NULL,          -- ISO-8601 UTC
    hash_partial  TEXT,
    hash_full     TEXT,
    algorithm     TEXT NOT NULL,          -- 'BLAKE3'
    hash_version  INTEGER NOT NULL,       -- 1
    last_seen_utc TEXT NOT NULL,
    PRIMARY KEY (volume_id, file_id)
);
CREATE TABLE IF NOT EXISTS cache_meta (
    key   TEXT PRIMARY KEY,               -- e.g. 'schema_version'
    value TEXT NOT NULL
);
```

3. **Input validity:** cache hit requires exact match of `(volume_id, file_id)` **and** `size` **and** `mtime` **and** `algorithm` **and** `hash_version`. Any divergence ⇒ recalculation. `hash_full` in cache is only accepted if `size ≤ 128 KiB` or if the file had L3 run in that scan — cache never promotes partial to full.
4. `mtime` compared with explicit, documented tolerance (2 s, FAT/NTFS rounding) — tolerance is conservative: on doubt, recalculate.
5. Path is never a primary key; stored only as optional informational metadata. Rename/move preserves file ID ⇒ cache survives.
6. Write at the end of each stage (not per file) in a single transaction; crash mid-write leaves the database consistent in the previous state (WAL).
7. Pruning: entries unseen for more than N days (default 180) are removed at scan start; idempotent operation.
8. `--no-cache` disables reads and writes (used by determinism tests to isolate variables).

## Consequences

- Formal contract in `docs/contracts.md` (`ICacheStore`).
- Mandatory tests: rename preserves hit; content change invalidates; `algorithm`/`hash_version` change invalidates everything.
