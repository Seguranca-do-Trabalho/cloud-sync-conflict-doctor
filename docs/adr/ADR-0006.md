# ADR-0006 — Cache incremental: SQLite via Microsoft.Data.Sqlite

- **Status:** Aceito
- **Data:** 2026-08-22
- **Decidido por:** Architect (card T01)

## Contexto

§12 manda cache local em SQLite com modelo mínimo (`file_id, size, mtime, hash_partial, hash_full, algorithm, hash_version, last_seen`), chave lógica por **file ID/inode** (não caminho) para que renomear/mover não invalide cache. ADR-0001 já fixou `Microsoft.Data.Sqlite`.

## Decisão

1. Pacote **`Microsoft.Data.Sqlite`** pinado; banco único em `%LOCALAPPDATA%/ConflictDoctor/cache.db` (CLI e GUI compartilham). WAL habilitado; acesso exclusivo do processo — sem servidor, sem rede (§26).
2. Schema v1:

```sql
CREATE TABLE IF NOT EXISTS file_hash_cache (
    volume_id     TEXT NOT NULL,          -- identidade do volume (file ID é só único dentro dele)
    file_id       TEXT NOT NULL,          -- NTFS file ID / inode-like, como texto estável
    size          INTEGER NOT NULL,
    mtime_utc     TEXT NOT NULL,          -- ISO-8601 UTC
    hash_partial  TEXT,
    hash_full     TEXT,
    algorithm     TEXT NOT NULL,          -- 'BLAKE3'
    hash_version  INTEGER NOT NULL,       -- 1
    last_seen_utc TEXT NOT NULL,
    PRIMARY KEY (volume_id, file_id)
);
CREATE TABLE IF NOT EXISTS cache_meta (
    key   TEXT PRIMARY KEY,               -- p.ex. 'schema_version'
    value TEXT NOT NULL
);
```

3. **Validade de entrada:** hit de cache exige correspondência exata de `(volume_id, file_id)` **e** `size` **e** `mtime` **e** `algorithm` **e** `hash_version`. Qualquer divergência ⇒ recálculo. `hash_full` em cache só é aceito se `size ≤ 128 KiB` ou se o arquivo teve L3 executado naquele scan — o cache nunca promove parcial a completo.
4. `mtime` comparado com tolerância explícita e documentada (2 s, FAT/NTFS rounding) — a tolerância é conservadora: na dúvida, recalcula.
5. Caminho nunca é chave primária; é armazenado apenas como metadado informativo opcional. Renome/move preservam file ID ⇒ cache sobrevive.
6. Escrita ao fim de cada estágio (não por arquivo) em transação única; crash no meio da escrita deixa o banco consistente no estado anterior (WAL).
7. Poda: entradas não vistas há mais de N dias (padrão 180) são removidas no início do scan; operação idempotente.
8. `--no-cache` desativa leitura e escrita (usado pelos testes de determinismo para isolar variáveis).

## Consequências

- Contrato formal em `docs/contratos.md` (`ICacheStore`).
- Testes obrigatórios: renome preserva hit; mudança de conteúdo invalida; troca de `algorithm`/`hash_version` invalida tudo.
