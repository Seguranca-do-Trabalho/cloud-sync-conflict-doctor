# ADR-0010 — Quarentena: layout, manifesto e restore (detalhamento do ADR-0002)

- **Status:** Aceito
- **Data:** 2026-08-22
- **Decidido por:** Architect (card T01)

## Contexto

ADR-0002 fixou a política (nunca delete; move para quarentena; manifesto; restore sem sobrescrever). Este ADR detalha layout físico, formato do manifesto e semântica exata de move/restore para implementação em EPIC 08.

## Decisão

### 1. Layout

```text
<raiz escaneada>/ConflictDoctor/
    quarantine/
        <op_id>/                       # um diretório por operação
            manifest.json
            payload/
                0001.dat               # nomes opacos, sem relação com o original
                0002.dat
```

`<op_id>` = `yyyyMMddTHHmmssZ-<8 hex determinísticos>`: timestamp UTC da operação + sufixo derivado do conteúdo do manifesto (BLAKE3 truncado), nunca aleatório puro — duas execuções da mesma resolução sobre o mesmo estado geram o mesmo id. Nomes opacos no `payload/` evitam colisão entre arquivos homônimos e expõem menos informação que o nome original.

### 2. Manifesto

`manifest.json` conforme §18, com campos adicionais obrigatórios:

```json
{
  "manifest_version": 1,
  "operation_id": "20260822T194500Z-a1b2c3d4",
  "created_utc": "...",
  "items": [ {
    "original_path": "<caminho absoluto original>",
    "quarantine_path": "<payload/0001.dat>",
    "size": 123,
    "mtime_utc": "...",
    "hash": "<blake3 hex>",
    "algorithm": "BLAKE3",
    "hash_version": 1,
    "reason": "IDENTICAL_DUPLICATE",
    "rule": "KEEP_NEWEST"
  } ],
  "status": "completed"
}
```

Escrita do manifesto: atômica — grava `manifest.json.tmp`, `File.Move(..., overwrite: false)`, e só então a operação é considerada concluída. Ordem por item: **move primeiro, registra depois**; falha no meio ⇒ `status` reflete o estado real e itens não movidos não aparecem como movidos.

### 3. Move

- `File.Move(original, quarantine_path)` — única API destrutiva-permissiva do produto; nenhum `File.Delete` em código de produção (revisão estática, §2 do ADR-0002).
- Antes do move: revalidar `size + mtime` contra L0 (TOCTOU); divergente ⇒ item marcado `skipped_stale_metadata` no relatório da operação, arquivo permanece onde está.
- Falha de move ⇒ processo termina conservadoramente (ADR-0002 §4); itens já movidos permanecem registrados no manifesto parcial com `status: "partial"`.

### 4. Restore

1. Ler manifesto; validar hash BLAKE3 de cada `payload/*.dat`.
2. Destino = `original_path`. Se ocupado: **nunca sobrescrever** — restaura ao lado com sufixo `.restored-<op_id>` e registra a variação no resultado.
3. Recriar diretórios pais ausentes.
4. Restore bem-sucedido marca o item (`status` do item → `restored`) reescrevendo o manifesto atomicamente; histórico nunca é apagado.

### 5. Testes obrigatórios (§22)

- move ⇒ original inexistente, quarentena existente, manifesto existente;
- restore ⇒ original de volta, hash preservado;
- restore sobre destino ocupado ⇒ sem sobrescrita, arquivo restaurado ao lado;
- grep/analyser provando ausência de chamadas delete em src/.

## Consequências

- Contrato formal em `docs/contratos.md` (`IQuarantine`).
- GATE 3 só abre após estes testes passarem.
