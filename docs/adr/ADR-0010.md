# ADR-0010 — Quarantine: layout, manifest, and restore (detailed from ADR-0002)

- **Status:** Accepted
- **Date:** 2026-08-22
- **Decided by:** Architect (card T01)

## Context

ADR-0002 fixed the policy (never delete; move to quarantine; manifest; restore without overwriting). This ADR details the physical layout, manifest format, and exact move/restore semantics for implementation in EPIC 08.

## Decision

### 1. Layout

```text
<scanned root>/ConflictDoctor/
    quarantine/
        <op_id>/                       # one directory per operation
            manifest.json
            payload/
                0001.dat               # opaque names, no relation to original
                0002.dat
```

`<op_id>` = `yyyyMMddTHHmmssZ-<8 deterministic hex>`: UTC timestamp of the operation + suffix derived from manifest content (truncated BLAKE3), never pure random — two runs of the same resolution on the same state generate the same ID. Opaque names in `payload/` avoid collision among same-named files and expose less information than the original name.

### 2. Manifest

`manifest.json` per §18, with additional mandatory fields:

```json
{
  "manifest_version": 1,
  "operation_id": "20260822T194500Z-a1b2c3d4",
  "created_utc": "...",
  "items": [ {
    "original_path": "<original absolute path>",
    "quarantine_path": "<payload/0001.dat>",
    "size": 123,
    "mtime_utc": "...",
    "hash": "<blake3 hex>",
    "algorithm": "BLAKE3",
    "hash_version": 1,
    "reason": "IDENTICAL_DUPLICATE",
    "rule": "KEEP_NEWEST"
  } ],
  "status": "completed"
}
```

Manifest write: atomic — writes `manifest.json.tmp`, `File.Move(..., overwrite: false)`, and only then is the operation considered complete. Order per item: **move first, record after**; failure mid-way ⇒ `status` reflects the actual state and items not moved do not appear as moved.

### 3. Move

- `File.Move(original, quarantine_path)` — the only destructive-permissive API in the product; no `File.Delete` in production code (static review, §2 of ADR-0002).
- Before move: revalidate `size + mtime` against L0 (TOCTOU); divergent ⇒ item marked `skipped_stale_metadata` in the operation report, file stays where it is.
- Move failure ⇒ process terminates conservatively (ADR-0002 §4); already-moved items remain recorded in the partial manifest with `status: "partial"`.

### 4. Restore

1. Read manifest; validate BLAKE3 hash of each `payload/*.dat`.
2. Destination = `original_path`. If occupied: **never overwrite** — restores alongside with `.restored-<op_id>` suffix and records the variation in the result.
3. Recreate missing parent directories.
4. Successful restore marks the item (`item status` → `restored`) by rewriting the manifest atomically; history is never deleted.

### 5. Mandatory tests (§22)

- move ⇒ original nonexistent, quarantine exists, manifest exists;
- restore ⇒ original back, hash preserved;
- restore onto occupied destination ⇒ no overwrite, file restored alongside;
- grep/analyser proving absence of delete calls in src/.

## Consequences

- Formal contract in `docs/contracts.md` (`IQuarantine`).
- GATE 3 opens only after these tests pass.
