# ADR-0001 — Linguagem e stack: C#/.NET 8

- **Status:** Aceito
- **Data:** 2026-08-22
- **Decidido por:** Orquestrador (card T01), conforme padrão da casa (SMB Speed Doctor)

## Contexto

O produto é local-first para Windows, com GUI real de aplicativo de consumidor, CLI desde o dia um, scanner de alta performance sobre filesystem Windows, cache em SQLite e testes determinísticos obrigatórios. O autor já mantém outro produto na mesma família de requisitos (SMB Speed Doctor) em C#/.NET 8 com solução Core/Cli/Gui/Tests.

## Decisão

C#/.NET 8, solução multi-projeto:

```text
CloudSyncConflictDoctor.sln
├── src/Doctor.Core        (scanner pipeline, domain model, relatório — zero UI)
├── src/Doctor.Cli         (conflictdoctor scan <path> [--json] [--quiet])
├── src/Doctor.Gui         (GUI principal do produto)
└── tests/Doctor.Tests     (TDD; determinismo, placeholders, quarentena)
```

## Consequências

- BLAKE3 via pacote `Blake3` (NuGet) — algoritmo explícito no schema do relatório (`algorithm = BLAKE3`, `hash_version = 1`, `report_schema_version = 1`).
- SQLite via `Microsoft.Data.Sqlite`.
- Enumeração Level 0 usará `System.IO.Enumeration.FileSystemEnumerable` (metadados já presentes na enumeração) e P/Invoke para `FILE_ATTRIBUTE_*` quando necessário; a camada Windows-native (FindFirstFileEx/LARGE_FETCH, IOCTL_STORAGE_QUERY_PROPERTY) fica isolada em interface para o agente windows-native implementar sem afetar os contratos.
- Determinismo por ordenação byte-wise de caminho antes de qualquer saída.
