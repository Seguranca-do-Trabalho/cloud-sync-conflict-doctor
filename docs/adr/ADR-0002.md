# ADR-0002 — Safety: quarantine + restore, never direct delete

- **Status:** Accepted
- **Date:** 2026-08-22
- **Decided by:** Orchestrator (card T02)

## Context

The specification (§2.1) prohibits, without exception, direct deletion of user files. Every destructive operation must use dated quarantine + auditable manifest + verified restore.

## Decision

1. No product code calls permanent deletion APIs. The only permitted operation on user content is **move** to `<root>/ConflictDoctor/quarantine/<timestamp ISO>/`.
2. Each operation generates a JSON manifest with: operation_id, timestamp, original_path, quarantine_path, size, mtime, hash BLAKE3, algorithm, reason, rule.
3. Restore verifies conflicts and **never silently overwrites** an existing file.
4. Failure at any step → process terminates conservatively; nothing partial remains unrecorded.
5. Mandatory tests: non-destruction (§22), restore with preserved hash, absence of delete calls (static review by reviewer).

## Consequences

- Exit codes documented in CLI; GUI never offers "delete now" — only "move to quarantine".
- GATE 3 (Resolution Safety) blocks downstream until quarantine+restore pass their tests.
