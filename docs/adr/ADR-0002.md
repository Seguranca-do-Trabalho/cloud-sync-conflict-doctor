# ADR-0002 — Segurança: quarentena + restore, jamais delete direto

- **Status:** Aceito
- **Data:** 2026-08-22
- **Decidido por:** Orquestrador (card T02)

## Contexto

A especificação (§2.1) proíbe, sem exceção, deleção direta de arquivo do usuário. Toda operação destrutiva deve ser quarentena datada + manifesto auditável + restauração verificada.

## Decisão

1. Nenhum código do produto chama APIs de deleção permanente. Operação única permitida sobre conteúdo do usuário: **move** para `<raiz>/ConflictDoctor/quarantine/<timestamp ISO>/`.
2. Cada operação gera manifest JSON com: operation_id, timestamp, original_path, quarantine_path, size, mtime, hash BLAKE3, algorithm, reason, rule.
3. Restore verifica conflitos e **nunca sobrescreve** arquivo existente silenciosamente.
4. Falha em qualquer etapa → processo termina de forma conservadora, nada parcial permanece sem registro.
5. Testes obrigatórios: não-destruição (§22), restore com hash preservado, ausência de chamadas delete (revisão estática pelo reviewer).

## Consequências

- Exit codes documentados no CLI; GUI nunca oferece "apagar agora" — apenas "mover para quarentena".
- GATE 3 (Resolution Safety) bloqueia downstream até quarantine+restore passarem nos testes.
