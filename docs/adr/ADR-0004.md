# ADR-0004 — Scanner pipeline Level 0–3: serial decisions, parallel reads

- **Status:** Accepted
- **Date:** 2026-08-22
- **Decided by:** Architect (card T01)

## Context

§5 defines the scanner as a cascading pipeline (Level 0 enumeration → Level 1 grouping → Level 2 partial hash → Level 3 full hash). §11 separates **DECISION** (always deterministic and serial over an ordered set) from **READING** (parallelizable). §6 prohibits opening placeholders; §10 requires telemetry whose primary metric is the amount of bytes **not** read.

## Decision

Explicit stage pipeline in `src/Doctor.Core`:

| Stage | Input | Output | Execution |
|---|---|---|---|
| L0 Enumeration | root | `FileEntry` (metadata) | 1 thread per volume; output sorted by `PathOrder` |
| L1 Grouping | `FileEntry` | groups by `normalized_base_name + size` | serial |
| L2 Partial hash | L1 survivors | reduced groups | configurable pool (ADR-0007) |
| L3 Full hash | L2 survivors | identical duplicate / real divergence | configurable pool (ADR-0007) |

Structural rules:

1. Every decision stage consumes and produces collections ordered by the canonical rule (path in UTF-8 bytes; tie-break `mtime → size → path` — ADR-0003). No stage decides based on arrival order.
2. Only byte reading (L2/L3) is parallel; each result returns via an ordered channel to the serial coordinator before the next phase. Report order never depends on which thread finished first.
3. Placeholder detected at L0 (`FILE_ATTRIBUTE_OFFLINE`, `RECALL_ON_OPEN`, `RECALL_ON_DATA_ACCESS`, reparse point) marks `FileEntry.IsPlaceholder` and prevents any subsequent content access — the hasher refuses marked entries (ADR-0005). Tested invariant: `placeholder_bytes_read == 0`.
4. L0 does not traverse directory reparse points (junction/symlink): records in `placeholders[]`/error list and continues. Prevents cycles and induced downloads.
5. Conflict name normalization (L1): small, fixed, auditable, versioned list (`normalizer_version = 1`) with the patterns from §7 — `(conflicted copy)`, `-DESKTOP-XXXX`, `" (1)"`, `" (2)"`, `~$`, `.sb-<hex>`. No regex machine; vendor separation only with objective justification.
6. Each stage emits the counters from §10 (`files_enumerated`, `files_skipped`, `files_placeholder`, `files_partial_hashed`, `files_full_hashed`, `bytes_read`, `bytes_read_partial`, `bytes_read_full`). Optimizing means reducing bytes read, not seconds per se.

## Consequences

- Formal contracts in `docs/contracts.md` (`IFileEnumerator`, `IScanPipeline`).
- The Windows-native enumeration optimization (FindFirstFileEx/LARGE_FETCH, ADR-0001) is isolated behind the interface and does not alter these stages.
- Mandatory tests: determinism under distinct enumeration orders (§20) and `placeholder_bytes_read == 0` (§21).
