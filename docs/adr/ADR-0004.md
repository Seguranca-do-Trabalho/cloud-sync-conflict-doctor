# ADR-0004 — Scanner em pipeline Level 0–3: decisão serial, leitura paralela

- **Status:** Aceito
- **Data:** 2026-08-22
- **Decidido por:** Architect (card T01)

## Contexto

§5 define o scanner como pipeline em cascata (Level 0 enumeração → Level 1 agrupamento → Level 2 hash parcial → Level 3 hash completo). §11 separa **DECISÃO** (sempre determinística e serial sobre conjunto ordenado) de **LEITURA** (paralelizável). §6 proíbe abrir placeholders; §10 exige telemetria cujo métrica primária é a quantidade de bytes **não** lidos.

## Decisão

Pipeline de estágios explícitos em `src/Doctor.Core`:

| Estágio | Entrada | Saída | Execução |
|---|---|---|---|
| L0 Enumeração | raiz | `FileEntry` (metadados) | 1 thread por volume; ordenado por `PathOrder` na saída |
| L1 Agrupamento | `FileEntry` | grupos por `normalized_base_name + size` | serial |
| L2 Hash parcial | sobreviventes do L1 | grupos reduzidos | pool configurável (ADR-0007) |
| L3 Hash completo | sobreviventes do L2 | duplicata idêntica / divergência real | pool configurável (ADR-0007) |

Regras estruturais:

1. Todo estágio de decisão consome e produz coleções ordenadas pela regra canônica (caminho em bytes UTF-8; empate `mtime → size → path` — ADR-0003). Nenhum estágio decide com base em ordem de chegada.
2. Somente a leitura de bytes (L2/L3) é paralela; cada resultado retorna por canal ordenado ao coordenador serial antes da fase seguinte. A ordem do relatório nunca depende de qual thread terminou primeiro.
3. Placeholder detectado em L0 (`FILE_ATTRIBUTE_OFFLINE`, `RECALL_ON_OPEN`, `RECALL_ON_DATA_ACCESS`, reparse point) marca `FileEntry.IsPlaceholder` e impede qualquer acesso subsequente ao conteúdo — o hasher recusa entradas marcadas (ADR-0005). Meta testada: `placeholder_bytes_read == 0`.
4. L0 não atravessa reparse points de diretório (junction/symlink): registra em `placeholders[]`/lista de erros e continua. Previne ciclos e downloads induzidos.
5. Normalização de nomes de conflito (L1): lista fixa, pequena, auditável e versionada (`normalizer_version = 1`) com os padrões do §7 — `(conflicted copy)`, `-DESKTOP-XXXX`, `" (1)"`, `" (2)"`, `~$`, `.sb-<hex>`. Sem máquina de regex; separação por fornecedor somente com justificativa objetiva.
6. Cada estágio emite os contadores do §10 (`files_enumerated`, `files_skipped`, `files_placeholder`, `files_partial_hashed`, `files_full_hashed`, `bytes_read`, `bytes_read_partial`, `bytes_read_full`). Otimizar significa reduzir bytes lidos, não segundos por si só.

## Consequências

- Contratos formais em `docs/contratos.md` (`IFileEnumerator`, `IScanPipeline`).
- A otimização Windows-native de enumeração (FindFirstFileEx/LARGE_FETCH, ADR-0001) fica isolada atrás da interface e não altera estes estágios.
- Testes obrigatórios: determinismo sob ordens de enumeração distintas (§20) e `placeholder_bytes_read == 0` (§21).
