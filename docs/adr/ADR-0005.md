# ADR-0005 — BLAKE3 hashing: partial 64 KiB start+end, full only at cascade end

- **Status:** Accepted
- **Date:** 2026-08-22
- **Decided by:** Architect (card T01)

## Context

§4 requires explicit BLAKE3 in the report; §8 mandates partial hash of first + last 64 KiB only for grouping survivors; §9 reserves full hash for candidates passing level 2; §12 requires incremental cache with stable keys.

## Decision

1. NuGet package **`Blake3`**, version pinned in `Directory.Packages.props`. Output always lowercase hexadecimal; report fields: `algorithm = "BLAKE3"`, `hash_version = 1`.
2. `hash_version = 1` fixes the **entire** scheme: algorithm, window size, and concatenation order. Changing any of these requires bumping `hash_version` and fully invalidating the cache.
3. Partial hash (scheme v1):
   - `size ≤ 128 KiB` (131,072 bytes): single sequential read of the entire file in one BLAKE3 hasher.
   - `size > 128 KiB`: single open; feeds the hasher with window `[0, 64 KiB)` then `[size − 64 KiB, size)`, in that order.
   - The same bytes are never read twice for the same hash.
4. Full hash: integral BLAKE3, executed only on group members with more than one L2 survivor (§10: minimize `bytes_read_full`).
5. Empty file (`size == 0`): partial hash = full hash = BLAKE3 of zero bytes; no read.
6. **Safety gate:** `IHasher` receives `FileEntry` and throws `PlaceholderReadException` if `IsPlaceholder == true`. Automated invariant: `placeholder_bytes_read == 0` (§6, §21).
7. TOCTOU integrity: `size` + `mtime` captured at L0 are revalidated after reading; divergence ⇒ one recalculation; persisting ⇒ recorded as partial error (exit 3 from ADR-0008), never silenced or "best estimated".

## Consequences

- Formal contract in `docs/contracts.md` (`IHasher`).
- The cache (ADR-0006) stores partial and full hashes under a key validated by `size`/`mtime`/`algorithm`/`hash_version`.
